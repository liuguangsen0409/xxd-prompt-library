## 这个库怎么组织

每篇 Prompt 文章只收录一个 Panel 的**原始提示词**（风格的唯一审美权威）和风格速览；而所有 xxd-panel 仓库都共用的「运行适配器」与使用方法，统一放在本页，不在每篇文章里重复。

xxd-panel 是小小东的系列项目，共 60 个不同视觉风格的照片转绘 Prompt，每个 Panel 一个独立仓库。原始仓库还提供面向 Codex / Claude Code 的完整 Skill 封装（含脚本、偏好记忆与多语言版本），如有工程化使用需求，推荐直接使用原仓库。

## 原始提示词与运行适配器

原始提示词固定为 3:4 竖版上下分栏。想换布局、换比例、出壁纸时，**不是改写原始提示词**，而是在其后追加运行变量。这套追加规则叫"运行适配器"，核心原则：原始提示词管审美，适配器只管交付容器。

### 不可改写的边界

- 不总结、翻译、扩写或"优化"原始提示词；
- 不额外规划颜色、色板、材料、构图、留白、标题或微文案；
- 颜色逻辑保持原样：原始提示词要求从照片取色就取色；
- 用户选择的模式和尺寸只替换旧的 3:4 上下容器描述，不覆盖其余审美规则；
- 每张成品只追加一个模式块，不把多个模式一起发送。

### 公共交付前言

换容器时先追加这段前言，替换原始提示词中关于 3:4 上下分栏的容器描述：

```text
【本次模式交付覆盖｜当前成品】

本段是当前展示模式、现实来源可见性、最终画布与设备交付的最终依据，
完整替换原始提示词中关于旧 3:4、上下位置、等分区域和旧上下容器的描述。
原始提示词关于设计转译、主体身份、颜色、材料、质感、内部构图、留白、
文字气质与排版的规则继续保持有效。

REALITY VIEW 指原始提示词定义的真实照片或事实场景。
TRANSFORMED DESIGN 指原始提示词定义的设计转译结果。

最终画布：<比例和／或准确 WIDTHxHEIGHT>
构图方式：一次生成一张连贯的完整画布
精确分区：仅在用户明确要求时启用

颜色完全服从原始提示词已有的颜色处理逻辑。
除非用户明确提出颜色修改，否则不要增加、替换、概括或重新规划任何色盘。
```

### 四选一模式块

每张成品只追加其中一个：

::code-group
  ```text [TOP_BOTTOM 上下分栏]
  输出模式：TOP_BOTTOM
  整张画面的主结构只有上下两个主要部分：REALITY VIEW 在上，TRANSFORMED DESIGN 在下，共同组织完整画布。由图像模型根据原图、原始提示词和最终画布决定两部分的视觉比例、内部裁切或环境延展、留白与文字布局。
  ```
  ```text [LEFT_RIGHT 左右分栏]
  输出模式：LEFT_RIGHT
  整张画面的主结构只有左右两个主要部分：REALITY VIEW 在左，TRANSFORMED DESIGN 在右，从画布顶部到底部共同形成完整的左右构图。所有可见内容与文字都融入这套左右结构；由图像模型自主决定不对称宽度、内部裁切或环境延展与留白。
  ```
  ```text [DESIGN_ONLY 纯设计稿]
  输出模式：DESIGN_ONLY
  整张画面完全使用 TRANSFORMED DESIGN 的设计转译语言。REALITY VIEW 只作为不可见的主体身份、结构关系、颜色逻辑与事实依据；每个可见元素都属于原始提示词规定的设计转译结果，而不是未经转译的原始照片展示。
  ```
  ```text [WALLPAPER_PACK 壁纸包]
  输出模式：WALLPAPER_PACK
  设备：<本张已确定的 PHONE、IPAD、DESKTOP 或 WATCH>
  壁纸关系：<已确定的 INDEPENDENT 或 LINKED>
  为当前设备创作一张完整画布的 TRANSFORMED DESIGN 壁纸。REALITY VIEW 只作不可见参考；根据设备画布与可用屏幕空间重新构图，每个可见元素都属于设计成品。
  ```
::

### 三选一文字模式

模式块之后追加其中一种：

::code-group
  ```text [模型生成]
  TEXT MODE: ORIGINAL_PROMPT_GENERATED
  TEXT LANGUAGE: <用户确认的语言或地区>

  由图像模型按照原始提示词已有的文字生成逻辑生成。所有可见文字都应从当前图片的内容、气质或隐喻中自然生长。任何以事实或资料形式呈现的信息，必须来自用户提供、图片清晰可见或已经核实的真实信息；没有事实依据时，使用诗意而非事实性的表达。运行层本身不是画面文案的来源。
  ```
  ```text [用户准确文字]
  TEXT MODE: USER_EXACT
  TEXT LANGUAGE: <用户确认的语言或地区>
  TEXT: 「<用户准确文字>」

  逐字使用，不改写、不翻译、不纠错、不添加其他文案。
  排版方式与字体气质继续服从原始提示词。
  ```
  ```text [不要文字]
  TEXT MODE: NONE
  画面中不得出现任何字母、文字、数字、标题、标签、Logo 或伪文字。
  ```
::

## 怎么用

::steps
  ### 1. 复制原始提示词

  把对应 Panel 文章里的「原始提示词」整段逐字复制，作为请求的开头。默认就是 3:4 上下分栏、文字由模型生成，**只贴这一段就已经可用**。

  ### 2. 需要换容器时，追加运行变量

  换布局、比例或出壁纸时，在原始提示词之后依次追加：公共交付前言（把 `<比例>` 换成实际值）-> 四选一模式块 -> 三选一文字模式。

  ### 3. 其他要求逐字放最后

  如果还有明确要求（具体文案、指定尺寸等），逐字追加在全部内容的最末尾。
::

最终生成请求的拼装公式：

```text
原始提示词正文（逐字）
+ 公共交付前言
+ 一个已选模式块
+ 一种文字模式块
+ 用户明确提出的其他准确要求（若有，逐字放在最后）
```

## 完整拼装示例

以 [xxd-panel-001](/prompts/xxd-panel-001) 为例：想生成一张 **16:9 左右分栏**、文字使用你指定文案的图，最终请求 = 该 Panel 的原始提示词全文，再依次追加下面这段：

```text
【本次模式交付覆盖｜当前成品】

本段是当前展示模式、现实来源可见性、最终画布与设备交付的最终依据，
完整替换原始提示词中关于旧 3:4、上下位置、等分区域和旧上下容器的描述。
原始提示词关于设计转译、主体身份、颜色、材料、质感、内部构图、留白、
文字气质与排版的规则继续保持有效。

REALITY VIEW 指原始提示词定义的真实照片或事实场景。
TRANSFORMED DESIGN 指原始提示词定义的设计转译结果。

最终画布：16:9
构图方式：一次生成一张连贯的完整画布
精确分区：仅在用户明确要求时启用

颜色完全服从原始提示词已有的颜色处理逻辑。
除非用户明确提出颜色修改，否则不要增加、替换、概括或重新规划任何色盘。

输出模式：LEFT_RIGHT
整张画面的主结构只有左右两个主要部分：REALITY VIEW 在左，TRANSFORMED DESIGN 在右，从画布顶部到底部共同形成完整的左右构图。所有可见内容与文字都融入这套左右结构；由图像模型自主决定不对称宽度、内部裁切或环境延展与留白。

TEXT MODE: USER_EXACT
TEXT LANGUAGE: 简体中文
TEXT: 「秋日市集」

逐字使用，不改写、不翻译、不纠错、不添加其他文案。

```

把拼好的完整内容发给生图模型（原仓库默认使用 GPT Image），一次生成一张完整画布。
